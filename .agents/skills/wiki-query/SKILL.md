# wiki-query — 내 위키(내 논문 큐레이션)만 조합해 답하기

먼저 `wiki/index.md`를 읽어 어떤 논문·주제가 있는지 파악한다. `llmwiki`는 macOS/Linux `./llmwiki`, Windows `.\llmwiki.cmd`.

## 0. 원칙 (모든 모드에 적용)
1. **내 위키 안 자료만** 조합한다: `wiki/`(리뷰·주제·`source.md` 원문)와 `drafts/`.
2. **웹 검색 금지.** 웹 검색 도구(web search)·인터넷 열람을 쓰지 않는다. Codex 채팅에 웹 검색이 켜져 있어도 쓰지 않는다(비용·자원 절약, 근거를 내 위키에서 추적하기 위해). 기억 속 일반 지식을 쓸 때는 "위키 밖 일반 지식"이라고 밝히고 사실 근거로 쓰지 않는다.
3. 사실 문장마다 근거 꼬리표: `[근거: <slug> · p.N]`, `[근거: <slug> · Table N]`, `[근거: <slug> · Achievement]`. 검색 결과의 `cite` 값을 그대로 쓴다. 근거 없는 추론·제안은 `(가설)`.
4. 위키에 없으면 **「없음」이라고 분명히** 말한다. 논문 제목을 지어내거나 기억으로 채우지 않는다. 형식:
   ```
   **없음** — 내 위키(논문 n편)에는 「<질문 핵심>」에 대한 근거가 없어요.
   Zotero에 더 넣어 볼 논문 검색어(영어): "<검색어1>", "<검색어2>", "<검색어3>"
   넣는 법: Zotero 실습 컬렉션에 PDF를 넣고 `$wiki-ingest 최근 1편`
   ```
   일부만 있으면 있는 부분만 답하고, 빈 부분에 같은 형식으로 「없음」+검색어를 붙인다.
5. **모든 답의 끝에 「참고한 곳」 블록**(1절). 근거를 하나도 못 찾았으면 `참고한 곳: 없음(위키에서 찾은 근거 0건)`.
6. 검색 snippet만 보고 답하지 않는다. 상위 결과의 리뷰 섹션과 `source.md` 해당 페이지를 **직접 읽는다**.

## 1. 「참고한 곳」 블록 (답 맨 끝, 근거마다 한 줄)
```
---
**참고한 곳**
1. <짧은 제목> (<연도>) — `wiki/papers/<slug>/review.md#<섹션>` · 원문 p.N, p.M · 화면: `site/papers/<slug>/index.html#<섹션-id>`
2. …
화면 보기: 브라우저로 위 `site/…/index.html` 파일을 여세요(이 폴더 기준). 화면이 아직 없으면 「위키 화면 열어 줘」라고 말해 주세요.
```
- `<섹션>`은 리뷰 헤딩 그대로(Essence, Motivation, Achievement, How, Originality, Limitation & Further Study, Evaluation, Related Papers). `<섹션-id>`는 소문자·하이픈: `essence`, `limitation-further-study`.
- 원문 페이지는 쓴 꼬리표의 p.N을 모은다. 화면에서 원문은 `site/papers/<slug>/source.html#p-N`.
- 주소 서버(선택): `.llmwiki/serve.json`이 있을 때만 `llmwiki serve --status`를 한 번 실행해, 켜져 있으면 각 줄 끝에 ` · http://127.0.0.1:<포트>/papers/<slug>/`를 덧붙인다. 꺼져 있으면 마지막 줄에 "주소가 안 열리면 「이 폴더에서 위키 화면 다시 켜 줘」라고 말해 주세요."

## 2. 요청 유형 고르기
| 사용자가 묻는 모양 | 모드 |
|---|---|
| 질문에 대한 답, 요약 | A. 근거 답변 |
| "정말 있나? 어느 논문?" "○○ 한 연구 있어?" | F. 사실 확인 |
| "어떤 방법/접근이 더 좋을까?" "A vs B" | G. 비교·선택 |
| "어떤 아이디어가 좋을까?" "빈틈", "다음 연구" | D. 아이디어 발견 |
| "이 연구를 어떻게 더 확장할까?" | H. 연구 확장 |
| "내 연구질문 다듬어 줘" | I. 연구질문 다듬기 |
| "어떤 방법·데이터를 쓰면 좋을까?" | J. 방법·데이터 고르기 |
| "이 주장/논문의 약점·반론은?" | K. 반론·약점 찾기 |
| "깊게 조사: …", "자세히 조사해 줘" | L. 깊게 조사 |
| "이 문장/표현이 어디 있었지?" | B. 문구 찾기 |
| "○○ 구조도/그래프/표 찾아줘" | C. 그림·표 찾기 |
| "drafts/… 이어서 써줘" | E. 이어쓰기 |

**query와 synthesize 나누기**: query는 **채팅 답·짧은 제안**(파일을 만들지 않음, 원하면 "drafts/에 저장할까요?"). 서론 초안·결합 문서·공통 한계 표·주제 지도처럼 **긴 문서로 남길 것**은 `$wiki-synthesize`(결과는 `drafts/`). 답 끝에 필요하면 "문서로 남기려면: `$wiki-synthesize 결합 <slug1> + <slug2>`"처럼 안내한다.

**아이디어류(D·H·I·J)**: 반드시 **논문 2편 이상을 조합**한다(각 재료에 꼬리표). 위키에 1편뿐이면 그렇게 말하고, 나머지는 `(가설)` + 「없음」 형식의 검색어 제안.

## A. 근거 답변
1. `llmwiki search "<핵심어 2–5개>"` (리뷰·주제). 한국어/영어 원어 둘 다 시도. 부족하면 `--scope source`로 원문 페이지.
2. 답 형식: 결론 1–2문장 → 근거 bullet(각각 꼬리표) → 한계/불확실성. 논문끼리 다르면 차이를 명시.
3. 좋은 답은 "drafts/에 저장할까요?" → 저장하면 `llmwiki index` + `llmwiki log query "<질문>"`.

## F. 사실 확인 ("정말 있나?")
1. `llmwiki search`(wiki·source 둘 다)와 `llmwiki find "<핵심 문구>"`로 찾는다.
2. 첫 줄에 판정 하나: **있음**(논문·페이지) / **부분적으로 있음**(무엇이 다른지) / **없음**(0절 4번 형식).
3. 있음이면 원문을 2문장 이내로 `>` 인용 + 꼬리표. 비슷한 것만 있으면 "정확히 같은 내용은 없음"이라고 쓴다. 추측으로 "있을 것"이라고 하지 않는다.

## G. 비교·선택
1. 비교할 대상(방법·시스템·접근)마다 관련 리뷰의 How·Achievement·Limitation을 읽는다.
2. 기준표: `| 기준 | A | B | (C) |` — 기준 예: 대상·규모, 효과 크기, 근거 수준(RCT/사용자 연구/리뷰), 비용·구현 난이도, 한계. 칸마다 꼬리표, 위키에 없으면 "위키에 없음".
3. **조건부 추천**: "○○가 목표면 A, △△ 조건이면 B" 형식. 한쪽만 정답이라고 하지 않는다. 근거 없는 판단은 `(가설)`.

## D. 아이디어 발견
1. 관련 리뷰들의 `Limitation & Further Study`, `Originality`, `Related Papers`를 읽는다 (`llmwiki sections --name limitation,originality,related`).
2. 아이디어 3–5개, 각각: ① 어떤 빈틈에서 나왔나(2편 이상 꼬리표) ② 연구 질문 ③ 가능한 방법·데이터 ④ 위험. 근거 없는 부분은 `(가설)`.
3. 문서로 남기려면 `$wiki-synthesize 결합 …` 또는 `drafts/ideas-YYYY-MM-DD-<주제>.md`(새 파일 전 확인) + `llmwiki log draft "<제목>"`.

## H. 연구 확장
기준 논문의 Essence·How·Limitation을 읽고, 위키의 다른 논문을 재료로 네 방향을 각각 1–2개씩: **대상**(다른 학습자·연령·국가) · **맥락**(과목·현장·modality) · **방법**(설계·측정·분석) · **변수**(조절·매개·결과 변수). 각 제안에 "어느 논문의 무엇을 빌려 오나"(꼬리표)와 `(가설)`.

## I. 연구질문 다듬기
1. 사용자 질문을 그대로 적고, 위키 근거로 문제점을 짚는다(너무 넓음·이미 답이 있음·측정 불가 등, 꼬리표).
2. 다듬은 질문 2–3개(PICO처럼 대상·개입·비교·결과가 보이게) + 각 질문이 메우는 빈틈(꼬리표) + `(가설)`.

## J. 방법·데이터 고르기
위키 논문들의 How(설계·표본·측정·분석)를 표로: `| 방법/데이터 | 쓴 논문 | 장점 | 한계 | 내 질문에 맞나 |`. 끝에 조건부 추천 1–2개. 위키에 없는 데이터셋·도구 이름은 지어내지 않는다.

## K. 반론·약점 찾기
1. 대상 주장·논문의 Limitation과 Evaluation을 읽고, 다른 논문의 상반된 결과·다른 조건을 찾는다(`llmwiki related <slug>`, `llmwiki search "<반대 결과 핵심어>"`).
2. `| 약점/반론 | 근거(꼬리표) | 얼마나 치명적인가 | 보완 방법 (가설) |`. 저자가 인정한 한계와 리뷰어(에이전트) 판단을 구분한다.

## L. 깊게 조사 (위키 안에서만 하는 심층 조사)
1. **계획**: 질문을 3–6개 관점으로 나눠 먼저 목록으로 보여 준다(예: 효과 · 작동 방식 · 대상·맥락 · 비교 · 한계 · 남은 질문).
2. **관점별 검색**: 관점마다 `llmwiki search "<관점 핵심어>"`(한/영), 필요하면 `--scope source`·`llmwiki figures`, 재료 모으기는 `llmwiki sections --name <섹션> --slugs <찾은 slug들>`.
3. **연결 따라 넓히기**: 찾은 핵심 논문마다 `llmwiki related <slug>`(또는 review.md의 `## Related Papers`)로 아직 안 본 이웃 1–2편을 더 읽는다. 위키 밖으로는 나가지 않는다.
4. **관점별 문단**: 관점마다 한 문단(3–6문장, 문장마다 꼬리표). 근거가 1편뿐이면 "(근거 1편)", 없으면 "위키에 근거 없음" 또는 `(가설)`.
5. **종합**: 관점들을 엮은 결론 한 문단 + 서로 어긋나는 결과 + 남은 빈틈(「없음」 형식의 검색어 제안).
6. **「참고한 곳」**. 원하면 `drafts/deep-<주제-영문>-YYYYMMDD.md`로 저장(새 파일 전 확인) → `llmwiki index` → `llmwiki log query "깊게 조사: <주제>"`.

## B. 문구 찾기
1. `llmwiki find "<문구>"` — 대소문자·줄바꿈·하이픈 차이를 무시한 정확 일치, 결과에 페이지(p.N).
2. 없으면 핵심 단어로 `llmwiki search "<단어들>" --scope source`.
3. 원문을 2문장 이내로 `>` 인용하고 `[근거: <slug> · p.N]`. 비슷한 표현만 찾았으면 "정확히 같은 문장은 없음".

## C. 그림·표 찾기
1. `llmwiki figures "<무엇을 그린 그림인지>"` — 그림·표 캡션 검색, 결과에 PNG 경로.
2. 상위 PNG를 **직접 열어** 요청과 맞는지 확인한다.
3. 답: 그림 번호·페이지·캡션 요약·경로, 붙여 쓸 마크다운
   - drafts/에서: `![Figure 2](../wiki/papers/<slug>/figures/fig2.png)` / 주제 페이지에서: `![…](../papers/<slug>/figures/fig2.png)`
   - "원문 PDF 캡처 · 로컬 연구용"이라 공개 배포 시 저작권(라이선스)을 확인하라고 덧붙인다.

## E. 이어쓰기 (drafts/)
1. 대상 파일을 끝까지 읽고 문체·구조·이미 인용한 논문을 파악한다. 파일이 없으면 만들지 물어본다.
2. 쓸 내용을 위 A 방식으로 위키에서 찾는다.
3. **덧붙이기만 한다.** 기존 문장은 지우거나 고치지 않는다(고칠 점은 제안만). 추가 부분 앞에 `<!-- llmwiki: AI 추가 YYYY-MM-DD -->`.
4. 사실 문장마다 꼬리표 + 문단 끝에 리뷰 링크 `[제목](../wiki/papers/<slug>/review.md)`.
5. 끝나면 `llmwiki index` → `llmwiki log draft "<파일 이름> 이어쓰기"`(위키 화면이 있으면 자동 갱신).

## 하지 말 것
- 웹 검색·인터넷 열람, 근거 없는 수치·인용, 위키 밖 기억으로 답하기, 없는 논문 제목 지어내기.
- `source.md` 문단 통째 복사, 사용자 글 삭제·수정, 유료 API 사용.
- 「참고한 곳」 빠뜨리기.
